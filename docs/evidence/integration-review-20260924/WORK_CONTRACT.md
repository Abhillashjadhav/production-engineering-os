# External-review closure contract

Owner instruction: verify the other LLM's claims, fix confirmed issues autonomously, identify genuine product decisions, and publish the work on GitHub. Also establish whether repository access can grant access to the owner's local machine.

## Approved bounded outcome

- Enforce supported release gates and reject gates without executable bindings; never equate a process/evidence gate with unrelated passing product tests.
- Accept the real PMOS Product Decision Contract in the repository verifier, preserving the source document and explicit requirement/criterion links.
- Exercise PMOS handoff through the current PEOS runner to its terminal result, with successful and deliberately failing synthetic fixtures.
- Recheck the retained approved task-store candidate and negative controls without changing its contract, evaluator, freeze, product or historical claims.
- Check repository workflows and network defaults; repair confirmed local preview exposure without assuming access to the owner's laptop.

## Constraints

Use existing paths. No paid TypeSafe/model calls, new live generation claim, local Mac/Ollama claim, external messages or posts, applications, destructive migration, wholesale deletion, approval fabrication, frozen-grader changes, sandbox retries, direct main push, PR merge or deployment. Any test-issued approval is visibly synthetic and never substitutes for owner approval.

The preserved task-store result is **DEMONSTRATED FOR THE APPROVED FEATURE** under the already authorized container-process fallback. A replay is not a new live generation or a general production-readiness claim. The new stricter compiler must reject that unchanged contract's description-only gates until a separately approved executable mapping exists.

## Verification and ownership

Runtime, handoff, verifier adapter and loopback-default fixes are separate reversible units. Each implementation has a reproduced failure, focused checks, source identities and independent review. Broaden testing only for concrete regression risk or repository gates. Root assembles evidence and GitHub PRs; implementation agents cannot approve their own completion.

The external LLM review supplies leads to verify, not authority or established facts. Claims without accessible source/evidence remain unverified. No inference from model agreement establishes repository correctness.

## Terminal reporting

Report what changed, exact tested/published heads, checks run, unresolved decisions and limitations. Keep implemented, verified, published, merged and deployed distinct. Close this bounded engineering work without claiming that every project or every future contract is ready.
