**SEC-LOCAL-001 — verified local exposure default in PEOS main.** `products/pm-evals-web/frontend/package.json:10,12` supplies `--host 0.0.0.0`; `frontend/vite.config.ts:24,30` also sets wildcard hosts. `scripts/preview.sh:23` starts that frontend. Both Vite modes proxy `/api` to the backend. Starting these commands directly can make the dashboard and proxy reachable to network peers when firewall/routing permit it. This does not establish Internet exposure or arbitrary Mac shell access. [Vite documents wildcard binding and the host override](https://vite.dev/config/server-options).

The Docker path has a different boundary: `docker-compose.yml:22,29` publishes backend and frontend on `127.0.0.1` only. `frontend/Dockerfile` builds static assets and serves them through nginx; it does not run Vite at runtime. The nginx listener is inside the container. The local Playwright configuration and preview script use loopback URLs. Therefore a loopback default in the existing Vite config and npm scripts is compatible with these callers. Retain Vite's explicit `--host 0.0.0.0` CLI option for intentionally reachable previews; document it as deliberate sharing. No repository-owned managed-preview requirement for wildcard binding was found. The existing toolchain test hardcodes the old start command and must change with the fix.
